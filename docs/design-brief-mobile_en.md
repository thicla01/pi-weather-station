# Brief — Mobile layout for pi-weather-station

## Context

**pi-weather-station** is an open-source weather station that runs on a Raspberry Pi 7" in kiosk mode. The app shows real-time weather, an animated radar (RainViewer), forecasts, government alerts (ECCC/NWS), and an AI summary generated by Claude.

**Current stack:**

- React 18 + CSS Modules (kebab-case → camelCase via css-loader)
- Leaflet + Mapbox tiles
- i18next (EN/FR/ES)
- Express backend, deployed on 7 Pis in production

**Two existing layouts:**

- `LayoutPi` (800-1279px) — 2-column grid, dock at the bottom, touch-optimised for the 7" kiosk
- `LayoutDesktop` (≥1280px) — full-screen map, floating right rail, overlaid dock

**Mobile = new layout** targeting `<800px` (in practice 375-430px portrait on phones).

---

## Existing design system to respect

**Palette** — four variants driven by the local time of day via CSS tokens:

- `day` — warm cream background `#fffaf0`, warm-brown accent
- `dusk` — orange transition
- `night` — anthracite background, amber accent
- `nightRed` (night-vision mode) — black background, everything in dark red `#c44040` ("blood moon" palette)

Key tokens: `--c-bg`, `--c-surface`, `--c-text`, `--c-text-dim`, `--c-accent`, `--c-accent-soft`, `--c-border`, `--c-border-hybrid`

**Hybrid mode** — when a severe government alert is active, surfaces become more opaque + coloured side strip (amber for moderate, red for severe).

**Typography** — Geist (geometric sans-serif), 13-16px body, 24-72px hero

**Icons** — IBM Carbon (24×24, 2px stroke) for UI controls, weather-icons (wi) for weather conditions

---

## Two variants to mock in parallel

### Variant A — Roaming companion (quick read)

**Use case:** the user checks the weather quickly from their phone when they are NOT in front of the Pi. Mostly read-only, very little interaction.

**Characteristics:**

- Single scrollable view (no tabbed navigation)
- Vertical stack: alerts → current weather → radar → 24h → 5 days → AI summary
- No access to settings / debug / API keys (those functions live on the local Pi)
- Minimal interactions: pull-to-refresh, tap to switch dark/light, tap marker on map
- Optimised for glanceability — all useful info in 2-3 swipes

**Expected benefits:** simple, fast to load, zero learning curve
**Limitations:** no configuration possible from mobile

### Variant B — Full app in miniature

**Use case:** same app as the Pi, just adapted to portrait. The user can do everything from their phone.

**Characteristics:**

- Tab navigation at the bottom (tab bar) or side drawer
- Suggested tabs: **Weather** (hero+alerts+AI summary) / **Map** (radar+timeline) / **Forecasts** (24h+5d) / **Settings** (params+debug if localhost)
- All Pi dock controls accessible (auto mode, red palette, marker, legend, etc.) — either in a condensed dock, or in Settings
- Full settings: API keys, units, language, sleep mode, etc.

**Expected benefits:** functional parity with the Pi
**Limitations:** more complex, more surfaces to design, more i18n to manage

---

## Constraints common to both variants

- **Touch-first** — targets 44×44 px minimum, generous spacing
- **Adaptive palette** — each mock must show at least `day` and `night` (and ideally `nightRed` for variant A since night-time use is a frequent case)
- **i18n** — texts in EN/FR/ES, allow for length variations (French is ~20% longer)
- **Safe areas** — respect iOS notches and the Android gesture bar
- **PWA-ready** — splash screen + home-screen icon planned for both variants
- **Performance** — the Leaflet map must stay smooth; avoid expensive effects (minimise `backdrop-filter`)
- **No heavy bottom-sheet modals** — the app is used for short check-ins, not long sessions

## Expected deliverables

For each variant:

1. **3-5 key screens** in 390×844 portrait (iPhone reference)
2. The **same primary screen** declined in 2 palettes (day + night minimum)
3. An **alert state** (hybrid mode with red strip)

Plus:

- **Comparison table** A vs B on axes: complexity, learning curve, value added vs the Pi, implementation effort
- **Final recommendation** with rationale

## Additional notes

- The project is mature (v2.14.78), with ~150 existing i18n strings and a visual language established over 3 years. Mobile must extend that continuity, not reinvent it.
- The maintainer (a human) deploys via SSH + git pull on 7 production Pis. Any solution that requires a separate build/binary (native app) is out of scope. Mobile will be served by the same Express that already serves LayoutPi/LayoutDesktop.
- Public repo: <https://github.com/thicla01/pi-weather-station>
