# Trusting the Pi's self-signed certificate

This guide walks through installing the Pi's TLS certificate as a
trusted root on a personal device. It removes the browser's "Not
secure" warning and — more importantly — fixes the **iOS PWA
home-screen icon** problem (without trust, iOS rejects the
`apple-touch-icon` background fetch and falls back to a generic
"first letter of the page title" glyph).

> **Why is this needed?**
> The Pi runs HTTPS with a self-signed certificate (no external CA
> involved). Browsers and operating systems treat self-signed certs
> as untrusted by default. For the kiosk's own browser the cert is
> generated by the kiosk and recognised automatically; for any other
> device on the LAN (your phone, a laptop, a tablet), the certificate
> chain doesn't validate and the OS-level secure-fetch paths that
> some features rely on (PWA install, service workers, push
> notifications) refuse to operate.
>
> The fix is a **one-time, per-device** install of the Pi's cert as
> a trusted root. After that, the OS treats the Pi as a verified
> origin — same effect as having a real Let's Encrypt certificate,
> without needing a public domain.

---

## Quick path: from the app's Settings panel

The fastest install path. Works on iOS, Android, macOS, Windows,
and Linux:

1. On the device you want to set up, open the kiosk's URL
   (e.g. `https://<pi-ip>:8443`) and tap **Continue** through the
   browser's security warning. (The warning is the very thing this
   guide makes go away — but for now you need to accept it once to
   load the page.)
2. Open **Settings** in the app (gear icon in the bottom dock).
3. Section 1 (Local preferences) → scroll to the **"Trust this Pi
   on this device"** block at the bottom.
4. Tap **Download cert**. The file `pi-weather-cert.pem` is saved
   to your device.
5. Continue with the per-platform steps below.

The "Download cert" link points to `/api/cert.pem` which serves the
file with `Content-Type: application/x-x509-ca-cert` — iOS, Android,
and macOS all recognise that MIME and offer to install the cert
as a profile / system root.

## iOS / iPadOS (Safari + every other iOS browser)

1. After downloading `pi-weather-cert.pem`, iOS shows a banner:
   **"Profile Downloaded"**. Tap it.
   - If you missed the banner: **Settings → General → VPN & Device
     Management → Downloaded Profile**.
2. Tap **Install** in the top-right. Enter your device passcode.
3. Confirm any "this profile is not signed by a recognised CA"
   warning — that's the whole point (the Pi is the CA).
4. **Settings → General → About → Certificate Trust Settings**.
5. Find the entry for your Pi (named after the Pi's hostname or
   `localhost`) and **toggle it ON**.
6. Confirm the "Warning" dialog. Done.

After the trust is on:

- Reload the kiosk URL in Safari — the "Not Secure" warning is gone.
- Remove the existing home-screen icon (long-press → Remove Web Clip).
- Add to home screen again (Share → Add to Home Screen).
- The radar icon now shows correctly instead of the "P".

**One-cert-per-Pi note:** the Pi's certificate is generated with
the Pi's LAN IP and hostname in its Subject Alternative Name (SAN).
If you have multiple Pis, repeat the steps once per Pi. There is
no central CA — each Pi is its own root.

## Android (Chrome / Firefox / Samsung Internet)

Android's CA-install flow is more locked-down than iOS — what works
depends on the Android version and the OEM skin.

### Android 14+ (Pixel / stock Android)

1. After downloading, open **Settings → Security → More security
   settings → Encryption & credentials → Install a certificate →
   CA certificate**.
2. Tap **Install anyway** on the warning about CAs reducing security.
3. Pick the downloaded `pi-weather-cert.pem` file.
4. Confirm the certificate name and **Install**.

> Note: on Android 7+ apps must explicitly opt-in to user-added CAs
> via their network security config. Chrome and Firefox do opt in;
> some apps don't. For our use case (browser PWA install), Chrome's
> opt-in is what matters.

### Android 11-13

Same path as 14+, but the menu is under **Settings → Biometrics and
security → Other security settings → Install from device storage →
CA certificate**.

### Samsung One UI

The CA install path is **Settings → Biometrics and security → Other
security settings → Install from device storage**, but on recent
One UI versions the option is labelled **"VPN & app user
certificate"** and **"Wi-Fi certificate"** depending on intended use.
Pick the path that ends in **"CA certificate"**.

After install:

- Reload Chrome → "Not secure" warning gone.
- The PWA install prompt appears in the URL bar.
- Install → the radar icon shows on the home screen.

## macOS (Keychain Access)

1. Double-click the downloaded `pi-weather-cert.pem` — **Keychain
   Access** opens.
2. Confirm to add it to the **System** keychain (or **login**, if
   you only want it trusted for your user).
3. Find the certificate in the list. It's named after the Pi's
   hostname or `localhost`.
4. Double-click it. In the **Trust** section, set **"When using this
   certificate"** to **"Always Trust"**.
5. Close the window — macOS will prompt for your password to update
   the trust setting.

After: Safari and Chrome no longer warn about the Pi.

## Windows (Edge / Chrome / Firefox)

Edge and Chrome use the Windows certificate store; Firefox uses its
own store and needs a separate step.

### Edge / Chrome / IE

1. Double-click the downloaded `pi-weather-cert.pem`.
2. Click **Install Certificate**.
3. Choose **Local Machine** (system-wide) or **Current User**
   (just for you). Click **Next**.
4. Choose **"Place all certificates in the following store"** →
   **Browse** → select **"Trusted Root Certification Authorities"**
   → **OK** → **Next** → **Finish**.
5. Confirm the security warning.

### Firefox

Firefox has its own trust store independent of Windows.

1. **Preferences → Privacy & Security → Certificates → View
   Certificates**.
2. **Authorities** tab → **Import**.
3. Pick `pi-weather-cert.pem`.
4. Check **"Trust this CA to identify websites"**. Click **OK**.

## Linux desktop (Chrome / Firefox)

Most desktop browsers on Linux use the NSS shared database under
`~/.pki/nssdb`. The `certutil` tool from `libnss3-tools` (Debian/
Ubuntu) or `nss-tools` (Fedora) is the easiest way to add a cert:

```bash
sudo apt install libnss3-tools     # Debian / Ubuntu
sudo dnf install nss-tools         # Fedora / RHEL

certutil -A -n "Pi Weather Station" \
  -t "C,," \
  -i pi-weather-cert.pem \
  -d sql:$HOME/.pki/nssdb
```

Firefox has its own database; either use Firefox's UI (see Windows
section above) or pass `-d sql:$HOME/.mozilla/firefox/<profile>/`.

## When to re-do this

The Pi's certificate is generated with an **825-day** validity
period. The kiosk regenerates it automatically when the cert is
within 30 days of expiry or when the LAN configuration changes
(e.g. you assigned a new static IP to the Pi). Either event
invalidates the old trust profile, and you'll need to repeat the
install flow once per device.

There is no automatic renewal sync because the Pi is the entire
trust chain — no external CA to pull updates from. The 825-day
window is far enough out that this is essentially "set and forget"
for most installations.

## What if I just don't want the icon problem?

The fallback "P on black" letter icon is purely cosmetic. The app
itself works exactly the same — same data, same controls, same
PWA standalone mode if you install it. If you don't care about the
icon and want to skip the trust setup, that's a fine choice. The
only thing you'll miss is the radar glyph on the home screen.
